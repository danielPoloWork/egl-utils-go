# v1.1.0 — Spec v2.0 reconciliation

**Date:** 2026-07-27 · **Milestone:** M10

A specification draft for v2.0 was discovered after v1.0.0 shipped. Rather than treat it as a rewrite,
[ADR-0030](../adr/0030-spec-v2-reconciliation.md) sorted every delta into three buckets: **additive**
deltas land here in v1.1.0, **breaking** ones are ledgered for a possible `/v2`, and existing
**deviations** are maintained alongside the ADRs that justified them. This release is the additive
bucket, complete — thirteen items, no exported signature changed, and the v1.0.0 API-stability
commitment intact.

## New capability

- **`circuitbreaker.State()`** — observable breaker state, as a *pure* read-only observer: it reports
  the state the next call would be admitted under, including the lazy cool-down transition, without
  performing it. Polling it for metrics cannot perturb the machine.
- **`lifecycle.Trigger()`** — programmatic shutdown that unblocks a pending `WaitForSignals` exactly
  as a signal would. A trigger arriving *before* the wait latches rather than being lost.
- **`ratelimit.(*Limiter).Middleware()`** + `ErrLimited` — 429-on-deny HTTP admission. It sheds via
  `Allow` and never queues via `Wait`, because parking a request holds a goroutine and its connection
  and turns an over-budget burst into unbounded queueing.
- **`hash.HashPasswordCost()`**, `hash.Cost()` + `ErrInvalidCost` — a configurable bcrypt work factor
  with the accepted range enforced **in this module**, because `x/crypto/bcrypt` silently promotes a
  sub-`MinCost` value to the default and honours costs 4–9 verbatim. `Cost()` makes
  verify-and-rehash-on-login actionable.
- **`config.WithStructValidation()`** — tag-based validation in the same call that loads the file.
  Tags run before the existing `Validator`, so a `Validate` method can assume per-field validity.
- **`pubsub.WithDropOldest()`** — evict the oldest buffered message instead of refusing the new one,
  for state-like streams where a later message supersedes an earlier one.
- **`contrib/redishealth` and `contrib/pgxhealth`** — driver-backed `health.Check` probes as
  **separate modules**, so this module still imports no database driver or cache client. They install
  and tag independently (`contrib/<name>/vX.Y.Z`) and are **not** covered by this tag.

## Performance

- **`cache` is sharded internally** — 32 independently locked shards keyed by `maphash.Comparable`.
  The 90/10 read/write mix at 1 M entries across 8 goroutines improves from **349.8 ns to 46.6 ns
  (7.5× faster)**, because a `Set` no longer takes an exclusive lock across the whole keyspace. The
  API is unchanged; uncontended single-goroutine calls pay ~5 ns more for the shard hash, a trade
  recorded with its measurements in [ADR-0038](../adr/0038-cache-sharding.md).

## Correctness

- **`config.Load` now returns the zero `T` on every error path**, as its documentation always
  promised. It previously handed back the decode target, and both `encoding/json` and `yaml.v3`
  populate the fields they read *before* the one that fails — so a malformed file returned a
  partially configured struct behind an error, risking a security-relevant setting silently left at
  its zero value. Found by this release's new fuzz target.

## Verification added

- **Fuzzing** — `FuzzConfigLoader` and `FuzzValidatorTags` with committed corpora and a 10-minute CI
  budget. The validator target asserts a contract-shaped invariant rather than "never panics", since
  `validator.Struct` panics by design on tag misuse.
- **Import-graph enforcement** — ADR-0004's dependency rings and the layered import graph are now
  build-breaking, via depguard plus a resolved-graph assertion that catches what depguard cannot.
- **Coverage gate** — ≥ 85% of statements **per package**; a module-wide average could not have
  failed.
- **The NFR suite** — every NFR in the specification now has a measured number and a stated verdict
  ([report](../benchmarks/2026-07-26-nfr-suite.md)), with a nightly tracker. Hardware-independent
  properties are hard-gated; throughput and latency are reported, because shared CI runners move
  microbenchmarks by more than the threshold would allow.

## Known and deliberate

Two findings from the NFR work are recorded rather than silently absorbed:

- **NFR-01's "0 allocs/op" target is unachievable.** `context.WithValue`, `http.Request.WithContext`
  and each `Header.Set` allocate structurally, so any middleware that propagates a value through the
  context and writes a response header allocates. The measured floor is enforced as a ratchet budget
  instead — a target that can only fail enforces nothing. The specification target needs amending.
- **`middleware.HeaderName` is `"X-Request-ID"`, not Go's canonical `"X-Request-Id"`**, which costs
  two allocations per request inside `textproto.CanonicalMIMEHeaderKey` for no difference on the
  wire. Measured but not changed: it is an API-visible constant under the v1 commitment.

## Compatibility

Module `github.com/danielPoloWork/egl-utils-go`, unchanged import paths, and no change to any
exported signature or documented behaviour — upgrading from v1.0.0 requires no code change. The Go
floor is 1.25 (Linux/Windows/macOS on Go 1.25 & 1.26). Runtime dependencies are unchanged and still
within ADR-0004's budget; `govulncheck` reports no called vulnerabilities.

`contrib/redishealth` and `contrib/pgxhealth` are separate modules and are **not** released by this
tag; they carry their own driver dependencies and their own tags.

## Next

The `/v2` ledger in ADR-0030 holds the breaking deltas, chief among them raising bcrypt's default
cost from 10 to 12 — reachable today without a MAJOR bump via `HashPasswordCost(pw, 12)`.
