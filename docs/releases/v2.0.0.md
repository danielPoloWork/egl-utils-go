# v2.0.0 — The second major: one boundary, seven breaking changes, and every import rewritten

**Date:** 2026-07-30 · **Milestone:** 13 (`/v2` — `pkg/` layout and the ledger emptied)

Feature packages now live under `pkg/`, the module path carries its `/v2` suffix, and **all seven
breaking changes deferred at v1.0.0 were discharged in this single release**. That last part is the
whole design of this version: [ADR-0042](../adr/0042-post-1.0-compatibility-contract.md) made
[ADR-0030](../adr/0030-spec-v2-reconciliation.md) §2's ledger the only destination for a breaking
change, and a boundary opened and not used has to be opened again. **The ledger is now empty.**

The public surface is **141 exported identifiers across 22 packages** — the twenty-one feature
packages plus the module root — and the module floor stays **Go 1.25**. Nine of the module's eighteen
dependency modules left the graph.

## Upgrading

### 1. Rewrite the import paths (mechanical)

Every consumer import changes, because the module path did:

```
github.com/danielPoloWork/egl-utils-go/<pkg>   →   github.com/danielPoloWork/egl-utils-go/v2/pkg/<pkg>
github.com/danielPoloWork/egl-utils-go         →   github.com/danielPoloWork/egl-utils-go/v2
```

The second line is the module root, which still holds `utils.Version`. Twenty of the twenty-one
package names are unchanged, one is renamed (`errors` → `errx`), so the rewrite is three passes —
matching the closing quote is what keeps a `contrib/*` import (a separate module, see below) out of
the way:

```bash
M=github.com/danielPoloWork/egl-utils-go
P='cache|circuitbreaker|config|db|env|fanin|fanout|hash|health|lifecycle|logger|metrics'
P="$P|middleware|pubsub|ratelimit|retry|semaphore|syncpool|validator|workerpool"

# 1. the renamed package
find . -name '*.go' -exec sed -i -E "s#\"$M/errors\"#\"$M/v2/pkg/errx\"#g" {} +
# 2. the twenty that only moved
find . -name '*.go' -exec sed -i -E "s#\"$M/($P)\"#\"$M/v2/pkg/\1\"#g" {} +
# 3. the module root, for utils.Version
find . -name '*.go' -exec sed -i -E "s#\"$M\"#\"$M/v2\"#g" {} +
go mod tidy
```

The `#` delimiter is not a style choice — `$P` contains `|`, so the conventional `s|…|…|` form fails
with *unknown option to `s`*. This snippet was run against a file importing all four shapes (a
package, the root, the renamed `errors`, and a `contrib/*` module) and produces exactly the rewrite
described, leaving the `contrib` path alone.

Pass 1 changes the path but not the identifiers: unless you imported it under an alias, the
references also become `errx.Wrap`, `errx.Wrapf`, `errx.StackTracer`.

Nothing about `pkg/` is a Go requirement — it is a legibility decision, recorded with the measurement
that decided it in [ADR-0045](../adr/0045-pkg-layout-and-v2.md): the module root had grown to forty
entries, and the alternative layout the series uses elsewhere would have cost a consumer 34 extra
characters per import against `pkg/`'s 7.

### 2. Then fix the seven API changes

| Package | v1.1.1 | v2.0.0 | ADR |
|---|---|---|---|
| `errors` → **`errx`** | `errors.Wrap(err, msg)` captured a stack implicitly | `errx.Wrap(err, msg)`; add `errx.WithStack(err)` where a trace is wanted; read it with `errx.Frames(err) []Frame` | [0046](../adr/0046-errx-opt-in-stacks.md) |
| `cache` | `v, err := c.Get(k)`; `cache.NewInMemory[K,V](ttl)`; `cache.ErrNotFound` | `v, ok := c.Get(k)`; `cache.New[K,V](ttl)`; sentinel **removed** | [0047](../adr/0047-cache-comma-ok.md) |
| `workerpool` | `p.Stop(ctx)`; `workerpool.ErrPoolClosed` | `p.Close(ctx)`; `workerpool.ErrClosed` | [0048](../adr/0048-workerpool-close.md) |
| `pubsub` | `ch, unsub := br.Subscribe(topic, f)`; `br.Publish(topic, m)`; `WithDropOldest[T]()` | `ch := br.Subscribe(ctx, topic, f)` (cancel `ctx` to unsubscribe); `err := br.Publish(ctx, topic, m)`; `WithSlowSubscriberPolicy[T](pubsub.DropOldest)` | [0049](../adr/0049-pubsub-reshape.md) |
| `metrics` | `metrics.Prometheus(reg)(h)`; `metrics.Handler()` | `rec := metrics.New()`; `rec.Middleware()(h)`; `rec.Handler()` | [0050](../adr/0050-metrics-without-the-sdk.md) |
| `lifecycle` | `WaitForSignals(os.Interrupt, syscall.SIGTERM)` | `WaitForSignals(10*time.Second, os.Interrupt, syscall.SIGTERM)` — or `0` for exactly v1's behaviour | [0051](../adr/0051-lifecycle-shutdown-timeout.md) |
| `hash` | `HashPassword` produced bcrypt cost 10 | **nothing to edit** — it produces cost 12 (see below) | [0052](../adr/0052-hash-default-cost-12.md) |

Every one of those fails at compile time, which is the property that makes this upgrade safe to do
in one pass — with a single exception.

### 3. The one change no compiler will tell you about

**`hash.HashPassword` now produces bcrypt cost 12 instead of 10.** No identifier moved, no signature
moved, nothing in your code fails to build — and the CPU a login costs went up **×4.03**, measured
(57.7 → 232.3 ms per verification on the reference workstation). Verification costs the same as
hashing, and verification is the side every login pays.

So before you ship this upgrade:

- **Check that your login path can absorb it.** Roughly **4.3 verifications per second saturate one
  core**, on an endpoint an unauthenticated caller can reach.
- **Put admission control in front of it** if it is not there already —
  `ratelimit.(*Limiter).Middleware` sheds over-budget requests before the handler runs.
- **If it cannot absorb it, ask for the old factor explicitly:** `hash.HashPasswordCost(pw, 10)`. The
  accepted range is unchanged at 10–31, so cost 10 is still perfectly legal; it simply has to be
  written down now rather than inherited.

**No stored hash is invalidated and there is no data migration to run.** bcrypt encodes the work
factor in the hash string, so every hash your v1 deployment wrote keeps verifying, and they move to
12 as their owners log in — the verify-and-rehash-on-login pattern in the package documentation, with
`hash.Cost` reading a stored factor. Hashes belonging to users who never return stay at 10, which is
why that pattern is paired with a dormant-account policy rather than assumed to converge.

## What you get for it

**A smaller dependency graph.** Removing the Prometheus SDK from `metrics` took **nine of the
module's eighteen modules** with it — `client_golang`, `client_model`, and the seven that existed
solely to serve them — so `go.sum` went from 50 lines to 24. A consumer of this module no longer
inherits a metrics SDK, a protobuf runtime, or `golang.org/x/sys`. The cost is stated plainly: the
metrics endpoint no longer serves the 37 `go_*` / `process_*` / `promhttp_*` families `promhttp`
supplied for free, so a deployment that scrapes runtime metrics now mounts a Prometheus handler at a
second path — putting that dependency in the builds that want it.

**Cheaper hot paths, where the redesign happened to allow it.** Not a headline feature, and only
claimed where it was measured:

| Path | v1.1.1 | v2.0.0 |
|---|---|---|
| `errx.Wrap` (stackless chain) | 550.1 ns, 3 allocs | **37.1 ns, 1 alloc** |
| `metrics` record a request | 223.0 ns, 1 alloc | **63.4 ns, 0 allocs** |
| `metrics` scrape (9 series) | 48.4 µs, 436 allocs | **6.2 µs, 3 allocs** |

The `errx` figure is the interesting one: v1's `Wrap` paid 276 ns **even when it captured nothing**,
walking the error chain on every wrap to find a stack that was already there. Opt-in capture removed
the walk, not just the capture.

**Clearer contracts in four places.** `cache.Get` says presence with a boolean instead of a sentinel;
`workerpool` uses the same shutdown verb as the rest of the module; `pubsub` states its
never-blocking promise explicitly and reports what a publish lost instead of dropping silently; and
`lifecycle` can bound a shutdown without the caller abandoning the signal helper.

## What did not change

- **No feature was removed and no capability was dropped** — this major moved and renamed things, it
  did not shrink the library. The one deliberate loss is the `promhttp` runtime metrics named above.
- **Behaviour, except where listed.** `cache`, `workerpool` and `errx`'s origin-pointing traces
  behave exactly as v1 did; the pubsub accounting invariant and the default drop policy are unchanged;
  `metrics` keeps every cardinality guarantee ADR-0027 decided, now verified byte-for-byte against
  the reference encoder by a golden file captured while the SDK was still a dependency.
- **The quality bar.** All nine CI jobs, four policy checkers, the 85%-per-package coverage gate, the
  fuzz budget and the import-graph enforcement carried through the whole milestone. **Every one of the
  seven packages this major reshaped is at 100% statement coverage** — `errx`, `cache`, `workerpool`,
  `pubsub`, `metrics`, `lifecycle`, `hash` — verified at the release cut, not assumed from the PRs.
- **`contrib/*` versions independently** ([ADR-0040](../adr/0040-contrib-submodules.md)) and is
  untouched by this release: `contrib/redishealth` and `contrib/pgxhealth` still require the core's v1
  line, because ADR-0040 forbids a `replace` and requires the *released* core. They move to `/v2`
  immediately after this tag exists — that ordering is the reason it is roadmap 13.9 and not 13.8.

## Compatibility and support

- **v1.1.1 stays available and unaffected** at its own tag and import path. Go's major-suffix rule
  means both majors can coexist in one build graph, so a large consumer can migrate package by
  package rather than atomically.
- **v2 is now the supported line.** v1 receives security fixes only; there is no plan for further v1
  features, and the v1 ledger is closed because it is empty.
- **The next breaking change waits for a ledger, not a release.** ADR-0042's contract applies to v2
  exactly as it applied to v1: every exported identifier is frozen for the life of the major, and
  anything breaking accumulates in ADR-0030 §2 until a `/v3` is justified on its own merits.
