# 2026-07-27 — M13 opens: `/v2`, `pkg/`, and a layout decided by building both

## What got done

The session's opening question — *"can we move to `src/main/go/it/d4np/utils`?"* — came back at the
end, and this time it was not a question about Go's rules but a report that **the project had become
hard to read**. That complaint was correct and had nothing to do with the earlier argument: the root
held **forty entries**, twenty-one of them feature packages, with `README.md` buried among `fanin/`
and `syncpool/`.

- **The Maven tree was built, not argued about.** Twenty-one packages moved, imports rewritten across
  45 files, `go.mod` to `/v2`, all four policy tools repointed, depguard fixed, everything green.
  Then it was reverted, because the working version produced the number the argument had been
  missing: **86 characters** for a consumer import against `pkg/`'s 59 and v1's 52 — for a root
  listing *indistinguishable* from `pkg/`'s.
- **That is the finding worth keeping.** The clutter was never caused by packages being at the root;
  it was caused by there being twenty-one of them. **Any single parent directory fixes it equally.
  Only depth differs, and depth is charged to every consumer forever.** Three rounds of prose had
  not settled this; twenty minutes of `git mv` did.
- **`pkg/` it is** ([ADR-0045](../../../adr/0045-pkg-layout-and-v2.md), superseding ADR-0003), with
  the module opening `/v2`. Root: **40 entries → 19**.
- **Three shape decisions inside that**, each with a reason:
  - **`/v2` is a module-path suffix, not a directory.** The tree is not duplicated; v1 stays
    reachable at its own tags, which is exactly what lets `contrib/*` keep requiring the released v1
    until 13.9.
  - **The module root keeps its package.** An intermediate experiment moved `doc.go`/`version.go`
    into the tree and left the module with *no root package at all* — legal, and worse: `…/v2` stops
    being importable and pkg.go.dev loses its landing page. They are metadata, not features.
  - **`contrib/*` does not move and its tags do not change.** A contrib module path never carries
    the core's major suffix — which is also the bug described next.
- **The tooling needed more than a path edit, and one of the changes was a genuine trap.**
  `import_graph_lint.py` built contrib module paths as `MODULE + "/contrib/" + name`; with a major
  suffix that demands `…/v2/contrib/redishealth`, a module that does not exist. `REPO` is now
  separate from `MODULE`, and a shared `short_pkg()` strips `SRC_ROOT` as well, so `RUNTIME_DEPS`,
  `ALLOWED_INTERNAL_EDGES` and the coverage report stay written in short names instead of
  forty-character paths.
- **depguard's allowlist rejected the one edge it exists to permit.**
  `config-imports-only-validator` names `validator` by concrete path, so after the move it blocked
  `config → validator` — the *sanctioned* edge. A red build that looked like a violation and was a
  rule gone blind.
- **A false alarm worth recording, because the repo answered it.** Re-verifying the architecture
  rules by deliberate violation, depguard reported nothing for an injected `retry → cache` edge.
  That looked like the ADR-0035 failure mode repeating. It was not: the test used a **blank** import,
  and ADR-0035 documents precisely that depguard cannot see `import _ "…/sibling"` — which is *why*
  `import_graph_lint.py` exists as a second layer, and it caught it. Re-testing with a real import
  showed depguard firing correctly. **The knowledge was already written down; I had not re-read it
  before raising the alarm** — the same failure this repository spent the day fixing, this time mine.

## Where the project stands

**Milestone 13 open, 1 of 10.** Everything green: build, vet, 22 packages of tests, gofumpt,
golangci-lint at 0 issues, all four policy tools, and both architecture layers re-verified by
deliberate violation. `version.go` stays at 1.1.1 — the bump belongs to 13.10.

## How the next session resumes

**The ledger is being emptied in this same major**, which is the decision that makes the whole
milestone worth its cost. ADR-0042 made ADR-0030 §2 the only destination for a breaking change and
ADR-0041 recorded that deferred breakage is free at a `/v2` boundary *and only there*. Seven items
were waiting; a boundary opened and not used has to be opened again.

Order matters in two places:

- **13.9 (`contrib/*` → `/v2`) must run after the `v2.0.0` tag.** ADR-0040 forbids a `replace` and
  requires the *released* core, so contrib cannot reference `/v2` before it exists. Until then it
  keeps building against v1, which it does today.
- **13.5 and 13.6 are redesigns, not renames**, and should not be treated as ledger chores. 13.5
  reopens ADR-0006's *"Publish never blocks"* — the invariant ADR-0039's drop policies and the
  exactly-once delivered-or-reported accounting are both built on, and `Publish(ctx) error` implies
  it can now fail or wait. 13.6 is the only item that changes the **dependency graph**: dropping
  `prometheus.Registerer` from the surface would remove ADR-0004's ring-3 entry and the largest
  dependency in the tree, and whatever replaces it must preserve ADR-0027's bounded-cardinality
  guarantees.

Each item amends spec §5 for its own API change, and `spec_api_lint.py` fails the build when §5 and
`go doc` disagree — so the contract cannot drift behind the redesign the way it drifted behind
Milestone 10.

Also open, unchanged: the EADOS `render.py` still seeds `SRC_MAIN` unconditionally (upstream PR #357
fixed only the Go profile's comment), and `egl-util-cpp` still ships `it/d4np/util` against
ADR-0041's ruled `utils`.
