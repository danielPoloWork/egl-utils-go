# 2026-07-30 — v2.0.0 release cut: the milestone that outlives its own release

**Draft PR on `release/v2.0.0`.** `version.go` → 2.0.0, `[Unreleased]` rolled into
`docs/changelog/v2/v2.0.0.md`, release notes written and indexed, README badge moved, and
**ADR-0030 §2's ledger marked empty** — seven items deferred at v1.0.0, seven discharged in this one
major.

## Why the release ran before 13.9, and why that is not a shortcut

The maintainer asked for 13.9 (contrib → `/v2`). It cannot run yet, and I checked rather than
asserted:

```
go: github.com/danielPoloWork/egl-utils-go/v2@v2.0.0: invalid version: unknown revision v2.0.0
published: v0.1.0 v1.0.0 v1.1.0 v1.1.1
```

[ADR-0040](../../adr/0040-contrib-submodules.md) requires the **released** core and forbids both
shortcuts that would make CI green today. That is worth restating because the temptation is real: a
`replace ../..` is *ignored for anyone who depends on the module*, so the `contrib` job would validate
a configuration no consumer ever receives while the real `require` went unexercised. So the order is
**13.10 → tag → 13.9**, which the ROADMAP had already recorded and which the maintainer confirmed.

## The lint caught me over-claiming, and the fix was the honest one

I marked Milestone 13 complete in the README and the ROADMAP heading. `consistency_lint.py`:

```
[milestones] README marks Milestone 13 complete, but ROADMAP has unchecked item(s) in that milestone
```

It was right and I was wrong. **13.9 is genuinely not done**, so the milestone is not done — the
release does not close it. Both documents now say "v2.0.0 cut; 13.9 remains", and the ROADMAP heading
carries a sentence explaining why a milestone can outlive its own release: 13.10 ships the tag that
13.9 requires. Forcing the gate green by checking 13.9, or by renumbering it into a new milestone
(forbidden), would both have made the roadmap lie to save a glyph.

This is the second time this milestone that a policy checker refused a plausible-sounding claim, and
both times the claim was the thing that needed changing.

## The migration guide is one document, and its snippet was run

The ROADMAP line said the release notes carry the import-migration table, so **there is no separate
migration guide**: a standalone document repeating seven API entries is two documents free to drift,
and the notes are what a consumer actually opens from a release page.

The `sed` snippet in them was **executed against a fixture**, not written from memory, and it failed
the first time in a way worth recording:

- The conventional `s|…|…|` form dies with **`unknown option to 's'`**, because the alternation of
  twenty package names *is itself* a string of `|` characters. Delimiter changed to `#`.
- **Matching the closing quote is what protects `contrib/*`.** `github.com/danielPoloWork/egl-utils-go/contrib/redishealth`
  shares the core's path prefix but is a separate module that must keep its v1-style path; a rewrite
  anchored on `…/egl-utils-go/<lowercase>` would happily turn it into `…/v2/pkg/contrib/…`. Verified
  on a file importing all four shapes — a package, the module root, the renamed `errors`, and a
  contrib module — and the contrib line comes out untouched.

The entries were also **reordered from the changelog's newest-first into roadmap order** (13.1 → 13.8),
because 13.1's layout change is the one every other migration step sits on top of. Same reordering
decision as the v1.1.0 cut.

## What I re-measured instead of trusting

- **Per-package coverage at the cut**, not as inherited from seven PR descriptions: `errx`, `cache`,
  `workerpool`, `pubsub`, `metrics`, `lifecycle`, `hash` — all seven reshaped packages at **100%**.
- **The version-lockstep gate**, verified live by reverting `version.go` to 1.1.1: it fails on all
  three edges (README badge, latest changelog, latest release notes). A gate trusted at a release is a
  gate nobody has seen work.
- **The CI job count** — the notes say nine, which is what `ci.yml` actually defines (`build`,
  `consistency`, `quality`, `benchmark`, `contrib`, `coverage`, `imports`, `fuzz`, `race`). My own
  memory said eight, from before 10.13 added `contrib`.
- **`ADR-0041`'s standing obligation**, which is the kind of thing a release is the last chance to
  notice: its addendum in ADR-0030 §2 says that if the `/v2` bucket is ever opened, the *vanity module
  path* must be re-evaluated "in the same breath". It was — ADR-0045 considered `go.d4np.it/utils` and
  rejected it, at exactly that boundary. Discharged, not skipped.

## The ledger table says two things it would be easy to leave out

ADR-0030 §2 now carries a per-item discharge table. It states explicitly that an empty ledger is **not
a closed one** — ADR-0042 still names §2 as the only destination for a breaking change, so it is where
the next one accumulates — and that the ledger was **not transcribed literally**: three items shipped
wider than their entry (13.4 folded in `ErrPoolClosed`, 13.5 grew a three-valued policy, 13.6 removed
the dependency rather than only the API surface) and two shipped narrower than their shorthand
(`Close` kept `ctx`, `Subscribe` kept `topic`). The prose records what was promised; the ADRs record
what was decided, and pretending those are the same would quietly rewrite five arguments.

the GitHub Release. **Publish stays the human checkpoint** — and the queue is clear before this one:

Release at all, which is worth a decision at some point rather than a discovery.

Then **13.9** becomes possible and closes Milestone 13: both `contrib/*` modules move to
`require …/egl-utils-go/v2 v2.0.0`, imports to `…/v2/pkg/health`, with no `replace` and no `go.work`.

**Still carried, still not fixed:** `orchestrator/project.yaml` describes the v1 API and now also the
v1 version. It wants one scoped sweep; the natural moment was this release and I did not take it,
because a release PR that also rewrites a governance manifest is two changes wearing one hat.
