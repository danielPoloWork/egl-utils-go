# v1.1.1 — 2026-07-27

A performance fix with no API change, plus the repair of a CI gate that had been failing
unnoticed. Nothing in the public surface moved: upgrading from v1.1.0 needs no consumer change.

## Changed

- `middleware.RequestID` performs its header map access through the canonical spelling of the
  header name, removing **two allocations from every request**
  ([ADR-0044](../../adr/0044-canonical-header-key-for-map-access.md)).
  `http.Header`'s `Get` and `Set` run `textproto.CanonicalMIMEHeaderKey` on the key they are given
  and allocate whenever it is not already canonical — and `"X-Request-ID"` is not, since Go's
  canonical form is `"X-Request-Id"`.

  Measured, hardware-independent: `RequestID` **6 → 4** allocations per request, `Chain`
  **8 → 6**, `ChainWithLogger` **11 → 9**, `RequestIDGenerated` **7 → 5**, with bytes per operation
  falling alongside (`RequestID` 432 → 400 B). The NFR-01 ratchet is lowered to the new floor and
  verified to bind there.

  **`middleware.HeaderName` is unchanged** and still exported as `"X-Request-ID"`. Nothing
  observable differs: `http.Header.Set` already canonicalised the key before storing, so the header
  map and the bytes on the wire were `X-Request-Id` before this change as well. Milestone 10.10 had
  recorded this fix as blocked behind a MAJOR-only change to the exported constant; that
  attribution was wrong — the constant's *value* and the *cost of using it as a map key* are
  separable, and only the first is a compatibility question.

## Fixed

- CI's two `-race` jobs are green again, having failed on every push since 2026-07-26 — the
  `v1.1.0` release commit included
  ([BUG-0001](../../bugs/2026/07/BUG-0001-race-detector-breaks-allocation-and-pool-identity-assertions.md)).
  No data race was ever involved: four test assertions measure allocation counts and `sync.Pool`
  object identity, both of which the race detector deliberately perturbs, so they described an
  instrumented binary rather than the one consumers run. They are now excluded from `-race` builds
  via `//go:build !race` and still gate on all four ordinary CI cells. Test-only; no library
  behaviour was affected.

## Notes

- No exported identifier was added, removed, or changed. `tools/spec_api_lint.py` reports the same
  130 identifiers as v1.1.0.
- `go.mod` and `go.sum` are untouched; no dependency moved.
- The `contrib/*` submodules version independently and are unaffected: they were released
  separately as `contrib/redishealth/v0.1.0` and `contrib/pgxhealth/v0.1.0`.
